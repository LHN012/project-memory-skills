# 记忆架构

应该规范，记录什么，怎么样的结构去记录，防止信息冗余的同时，减少错误信息的产生。

## 一、层级划分

|    层级    | 作用                                                         | 维护方式   | 优先级 |
| :--------: | :----------------------------------------------------------- | ---------- | :----: |
|  library   | 知识库，跨项目级别的长久记忆                                 | 人工指定   |   低   |
| guardrails | 项目级规则，当前项目所适配的约束、规则、模板。               | 人工指定   |   高   |
|  modules   | 业务记忆层，记录项目业务模块功能文档、接口文档等             | 渐进式探索 |   中   |
|  changes   | 变更层，记录变更及变更原因，方便后续对修改产生的问题进行溯源 | 自动记录   |   低   |
|  lessons   | 经验层，积累实施过程中解决问题的经验                         | 自动记录   |   高   |
|   plans    | 计划层，存放复杂任务，批量任务等的实施计划                   | 人工指定   |   低   |

## 二、触发搜索条件

### plans层

| 场景                           | 触发方式                                       |
| ------------------------------ | ---------------------------------------------- |
| 执行或继续一个大需求           | 优先查对应计划，例如“继续实施工单迁移需求”     |
| 恢复复杂问题、查询进度或阻塞项 | 优先查计划，例如“上次做到哪了”“还有哪些待确认” |
| 开发具体功能，且关联已有计划   | 先读当前模块事实，再读取关联计划               |
| 准备创建或修订大需求计划       | 先查已有计划，避免重复创建                     |

### changes层

触发语义：

- 排查回归问题；
- 追溯历史原因；
- 评估是否可以回滚；
- 核对某次变更的影响范围；
- 用户明确指定日期文件、`change_id`、`issue` 或要求查询变更记录。

触发后，当前搜索顺序是：

1. 当前会话已有相关证据；
2. 按日期文件、`change_id`、`issue` 精确定位；
3. 按关键词、错误信息、状态等文本搜索；

## 三、规范化格式



### plans层

该层架构如下

```json
.codex/memory/plans/
    2026-10-09-v1.md
    2026-10-12-v2.md
```

具体文件中存储的内容

1. **需求来源文档**：来源文件、版本、章节或页码，对应哪些需求。
2. **需求目标与范围**：要解决的问题、本阶段交付内容及范围边界。
3. **需求计划清单**：逐条列需求，标记是否明确、能否立即实施、当前进度、阻塞项和验收条件。
4. **当前现状与影响范围**：相关页面、接口、模块的现状，以及会影响哪些旧功能。
5. **需求计划表结构**：哪些表需要新增、修改、删除或引用，字段及关联设计、数据迁移和回滚安排。
6. **需求待补充**：不明确的问题、P0–P3 影响等级、阻塞哪些需求、确认方和确认结果。未解决 P0 禁止实施受影响及依赖部分。
7. **依赖与前置条件**：前序需求、外部接口、权限、数据和环境是否就绪。
8. **需求实施计划**：各阶段的具体步骤、交付物、前置条件、执行状态和完成条件。
9. **验收标准与验证计划**：如何验证完成、在哪个环境验证、结果和证据。
10. **风险、回滚与决策记录**：风险、关键方案的依据，以及必要的撤回方式。
11. **计划变更记录**：范围、方案、版本或里程碑调整的原因和结果。



### changes层

该层架构如下

```json
按照日期创建文件，且jsonl格式易于机器使用
.codex/memory/changes/
  2026-06-23.jsonl
  2026-06-24.jsonl
  2026-09-15.jsonl
```

具体文件中的存储字段如下

```json
{
  "change_id": "CHG-20260915-003",
  "timestamp": "2026-09-15T10:12:56+08:00",
  "issue": "all_order_log_callers_migrated",
  "observation": "……"
}

change_id	当前变更记录的唯一编号	方便引用、去重和关联其他记录
timestamp	这次变更发生或确认的时间	用于排序；建议保留完整时区
issue	这次变更对应的问题或主题	用于搜索和归类，同一个问题可以出现多次
observation	对本次变更的完整记录	描述现象、原因、处理方式、验证结果和未确认事项
```



## 四、skills工作流

#### 1.`project-memory-init` Skill 

初始化时创建

```
.codex/memory/changes/
└── INDEX.md
```

它只负责：

- 创建 `changes/` 目录；
- 创建 `changes/INDEX.md`；
- 写入本层的用途、读取条件和格式规则。
