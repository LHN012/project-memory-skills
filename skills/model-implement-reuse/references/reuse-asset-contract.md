# 复用资产契约模板

`contract.md` 不是泛泛的说明文，而是复用资产的“边界协议”。无论资产类型是组件、功能块、服务层还是工具逻辑，至少应覆盖下面这些内容。

## 一、基础元信息

- 资产名称
- 资产类型：`component` / `feature` / `logic` / `mixed`
- 来源项目路径
- 来源模块或目录
- 当前状态：按 `references/status-contract.md` 使用 `draft` / `blocked` / `study-only` / `ready-for-extract` / `extracted`

## 二、职责边界

- 这个资产负责什么。
- 明确不负责什么。
- 它解决的核心问题是什么。
- 哪些行为仍应留在调用方或宿主模块中。

## 三、输入输出契约

- 输入参数、props、上下文依赖或前置条件。
- 输出事件、返回值、回调、副作用或持久化结果。
- 错误态、空态、加载态和异常分支。
- 是否存在同步/异步混合行为。

## 四、状态与权限

- 内部状态有哪些。
- 状态流转条件是什么。
- 是否依赖用户角色、数据范围或权限点。
- 哪些状态或权限必须由外部传入，哪些可由内部维护。

## 五、数据与接口依赖

- 依赖哪些表、字段、接口、DTO、缓存键或消息事件。
- 哪些依赖是强绑定的，哪些可以抽象成适配层。
- 如果迁移到其他项目，必须替换哪些数据源。

## 六、视觉与交互契约

适用于 UI 组件或界面区块：

- 组成组件有哪些，分别几个，主次层级怎样。
- 相对位置、间距、颜色、字号、边框、留白等关键视觉规则。
- 哪些视觉部分必须保持一致，哪些允许外部覆写。
- 是否有原型、截图或现有实现作为视觉基准。

## 七、扩展点与限制

- 调用方可扩展哪些点。
- 不允许扩展哪些点。
- 哪些参数是稳定契约，不能随意破坏。
- 哪些点仍待用户确认。

## 八、适用范围与禁用范围

- 适用于哪些页面、模块或项目。
- 不适用于哪些页面、模块或项目。
- 哪些条件下只能“参考使用”，不建议直接复用。
