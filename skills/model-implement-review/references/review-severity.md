# Review Severity

使用 `P0` 到 `P3` 标记发现严重级别。

## P0

阻塞上线或必须立即处理。

典型情况：

- 数据严重错误或丢失。
- 安全、权限或数据范围严重越权。
- 核心流程完全不可用。
- 会导致生产事故的事务、幂等或状态流转问题。

## P1

高风险问题，通常应优先处理。

典型情况：

- 明确业务回归。
- 关键接口契约错误。
- 重要状态流转错误。
- 常见路径功能失败。
- 权限控制存在明显漏洞但影响面可控。

## P2

中风险问题，建议处理但不一定阻塞。

典型情况：

- 边界场景缺陷。
- 异常处理不足。
- 部分验证缺失。
- 性能存在可见风险但尚未证明阻塞。
- UI 或交互与方案存在非阻塞偏差。

## P3

低风险问题，主要是健壮性、可维护性或一致性建议。

典型情况：

- 轻微可维护性问题。
- 低风险重复代码。
- 非关键提示文案或空态不足。
- 不影响主流程的小体验问题。

## 定级原则

- 优先按业务影响和数据风险定级，不按改动大小定级。
- 没有明确行为风险的问题，不要硬升 P1。
- 风格偏好默认不是 finding，除非会造成维护或行为风险。
