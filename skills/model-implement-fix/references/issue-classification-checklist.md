# 问题分类清单

在开始修复前，先判断问题属于哪一类。分类不是形式动作，它决定了依据来源、是否需要参考原型、修复范围和验证方式。

## 分类项

1. `视觉还原问题`
   - 例如颜色、字号、间距、对齐、层级、按钮样式、卡片样式、图标或布局与期望不一致。
   - 通常需要参考原型。
2. `交互一致性问题`
   - 例如显隐逻辑、按钮位置、弹窗/抽屉行为、联动关系、步骤切换、禁用态或反馈提示不对。
   - 可能需要参考原型；如果方案文档已写清则先按方案。
3. `数据展示问题`
   - 例如字段错位、字段缺失、格式化错误、排序错误、分页异常、空态错误。
   - 一般不需要参考原型，除非属于明显的页面展示还原问题。
4. `接口契约问题`
   - 例如请求字段错误、返回结构不匹配、字段命名不一致、错误码或空态口径不一致。
   - 一般不需要参考原型。
5. `业务逻辑问题`
   - 例如保存、提交、审核、删除、计算、状态切换逻辑错误。
   - 一般不需要参考原型。
6. `权限与数据范围问题`
   - 例如按钮误放开、角色权限错误、组织范围过滤错误、本人/本部门/全量口径错误。
   - 一般不需要参考原型。
7. `事务与幂等问题`
   - 例如重复提交、并发写入、回滚不完整、重复回调、数据重复生成。
   - 一般不需要参考原型。
8. `性能问题`
   - 例如慢查询、列表卡顿、接口耗时高、无索引、重复渲染。
   - 一般不需要参考原型。
9. `回归问题`
   - 例如某次修改导致既有功能失效、相邻模块联动异常、样式回退、接口兼容性破坏。
   - 是否参考原型取决于回归点是否与视觉/交互有关。
10. `环境或配置问题`
   - 例如构建失败、依赖缺失、环境变量错误、路由配置错误、部署参数不一致。
   - 一般不需要参考原型。

## 是否参考原型判断

满足任一条件时，才把原型列为输入：

- 问题属于 `视觉还原问题`。
- 问题属于 `交互一致性问题`，且现有方案文档没有写清期望行为。
- 用户明确提出“按原型修复”“与原型一致”“界面偏了”。
- 修复过程中发现仅靠方案和代码无法推断正确的界面表现。

默认不参考原型的情况：

- 纯后端 bug。
- 接口或 DTO 问题。
- 权限和数据范围问题。
- 事务、幂等、状态流转问题。
- SQL、性能、日志报错问题。

## 输出要求

在 `issue.md` 中至少记录：

- 问题分类结果。
- 是否需要参考原型。
- 判断理由。
- 当前问题会影响的验证范围。
