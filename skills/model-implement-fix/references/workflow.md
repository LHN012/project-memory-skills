# Fix Workflow

## Goal

`model-implement-fix` 用于轻量修复已经存在的问题或小范围实现偏差。核心目标不是重做功能，也不是强制补全完整项目信息，而是在必要且受控的影响面内定位根因、修复问题、验证回归，并把有价值的项目认知逐步沉淀到 init-read 报告和 memory。

## Workflow

1. 收集问题输入：用户描述、报错、日志、截图、复现步骤、相关模块、相关页面、相关接口、相关代码路径或可搜索关键词。
2. 判断问题类型：使用 `issue-classification-checklist.md` 先分类，明确它是视觉、交互、数据、权限、接口、状态、性能、回归、构建/配置或其他问题。
3. 判断是否需要额外上下文：
   - 普通小 bug 可直接读代码、日志和运行结果定位。
   - 权限、数据范围、状态流转、公共组件、SQL、业务规则、跨模块影响、方案/原型一致性问题，再按需查知识库、RAG、初始化报告、方案、SQL 或原型。
   - 项目没有初始化报告或 implement 方案时，不阻塞普通修复。
4. 判断是否需要查询知识库：
   - 默认不查。
   - 当前问题涉及强约束规则、公共组件、权限、数据范围、状态流转、SQL 兼容、样式规范或业务口径不清时，读取 `library/定义规则.md` 并查询命中资料。
   - 如果当前问题需要知识库而入口/命中资料缺失或规则冲突，停止相关风险修复并暴露问题。
5. 判断是否需要参考原型：
   - 默认不参考原型。
   - 只有视觉、布局、交互一致性问题，或用户明确要求按原型修复时才读取原型。
   - 如果当前依据无法确定期望界面表现，再升级为需要参考原型。
6. 确认期望行为依据：优先用户明确要求、当前问题描述与复现路径、当前代码真实实现；需要时再加入知识库规则、已确认方案文档、业务/数据库上下文和原型。
7. 复现或静态定位问题：记录输入条件、角色、数据状态、环境、复现路径或静态证据。
8. 根因分析：定位到代码、接口、数据、权限、状态、样式、配置或构建层。
9. 影响范围评估：看是否影响上下游页面、其他模块、列表/详情/编辑链路、统计、权限、SQL 或回归测试。
10. 必要且受控范围修复：避免把局部问题扩大成架构重写；涉及公共能力或跨模块影响时先评估是否需要人工确认。
11. 验证修复：按 `fix-validation-checklist.md` 检查原问题消失、相邻流程未坏、关键边界未破。
12. 按需沉淀报告：默认不生成 `issue.md` 与 `fix-result.md`；只有用户要求、问题复杂、跨模块、需要审计留痕或后续交接时才生成。
13. 沉淀记忆：把可复用的根因模式、修复经验、验证经验和项目认知写入 `memory/fix.jsonl`，必要时提升规则。
14. 补充初始化认知：修复中发现的项目基础事实，补充到对应 init-read 报告；不存在报告时可创建简短条目并标记待复核。

## Source Priority

修复时优先级建议如下：

1. 用户最新明确指令。
2. 当前问题描述、复现路径、日志、报错、截图和实际运行结果。
3. 当前代码真实实现和邻近实现模式。
4. `fix-rules.md` 与 `shared-rules.md` 中已经稳定的规则。
5. 按需读取的知识库入口和命中规则：`library/定义规则.md` 及其命中的具体资料路径。
6. 按需读取的已确认方案文档：`frontend-plan.md`、`backend-plan.md`、`module-relations.md`。
7. 按需读取的业务、数据库与材料上下文：`reports/init-read/初始化契约.md`、`代码及框架信息.md`、`已有功能模块信息.md`、`待办清单.md`、`业务理解.md`、`数据库审查报告.md`、`待确认点.md`。
8. 旧的 `reports/init-airead/shared-context.md`、`business-flows.md`、`db-assessment.md` 仅作为历史辅助输入，不替代新版初始化主报告。
9. 原型图：仅在问题类型或用户要求触发时加入。

## Stop Conditions

遇到以下情况应停下并暴露问题：

- 问题本质上是功能未实现，而不是实现错误。
- 当前问题需要知识库约束，但 `library/` 存在且 `library/定义规则.md` 缺失。
- 当前问题需要知识库约束，但命中的知识库必读资料缺失或无法读取。
- 必要知识库规则与用户要求、项目规则或方案文档冲突且优先级无法判断。
- 方案文档、用户要求与原型之间存在关键冲突。
- 缺少复现条件、期望行为依据或必要权限，无法安全修复。
- 修复范围已经明显超出“必要且受控范围修复”。
