# Fix Workflow

## Goal

`model-implement-fix` 用于修复已经存在的问题。核心目标不是重做功能，而是在尽可能小的影响面内定位根因、修复问题并验证回归。

## Workflow

1. 收集问题输入：用户描述、报错、日志、截图、复现步骤、相关模块、相关页面、相关接口。
2. 执行知识库门禁：读取 `library/定义规则.md`，识别当前修复命中的强制规则和用到时查询路径，读取所有命中的具体资料，并严格遵守；如果入口缺失、命中资料缺失或规则冲突无法判断优先级，停止，不改代码。
3. 判断问题类型：使用 `issue-classification-checklist.md` 先分类，明确它是视觉、交互、数据、权限、接口、状态、性能、回归或其他问题。
4. 判断是否需要参考原型：
   - 默认不参考原型。
   - 只有视觉、布局、交互一致性问题，或用户明确要求按原型修复时才读取原型。
   - 如果当前依据无法确定期望界面表现，再升级为需要参考原型。
5. 确认期望行为依据：优先用户明确要求、知识库规则、已确认问题描述、已确认方案文档、业务上下文；需要时再加入原型。
6. 复现问题：记录输入条件、角色、数据状态、环境和复现路径。
7. 根因分析：定位到代码、接口、数据、权限、状态或样式层。
8. 影响范围评估：看是否影响上下游页面、其他模块、列表/详情/编辑链路、统计、权限或回归测试。
9. 最小安全修复：遵守命中的知识库规则，避免把局部问题扩大成架构重写。
10. 验证修复：按 `fix-validation-checklist.md` 检查原问题消失、相邻流程未坏、关键边界未破。
11. 沉淀文档：更新 `issue.md` 与 `fix-result.md`，记录实际参考的知识库路径和规则遵守情况。
12. 沉淀记忆：把可复用的修复经验写入 `memory/fix.jsonl`，必要时提升规则。

## Source Priority

修复时优先级建议如下：

1. 用户最新明确指令。
2. 知识库入口和命中规则：`library/定义规则.md` 及其命中的具体资料路径。
3. 当前问题描述与复现路径。
4. 已确认方案文档：`frontend-plan.md`、`backend-plan.md`、`module-relations.md`。
5. 业务、数据库与材料上下文：`reports/init-airead/shared-context.md`、`reports/init-airead/business-flows.md`、`reports/init-airead/db-assessment.md`、`reports/init-airead/input-materials.md`。
6. 人读初始化辅助文档：`reports/init-read/功能模块清单.md`、`reports/init-read/待人工确认.md`，仅在需要确认页面归属、人工待确认项或用户侧表述时读取。
7. 原型图：仅在问题类型或用户要求触发时加入。
8. 当前代码和实际运行结果。
9. `shared-rules.md` 与 `fix-rules.md`。

## Stop Conditions

遇到以下情况应停下并暴露问题：

- 问题本质上是功能未实现，而不是实现错误。
- `library/` 存在但 `library/定义规则.md` 缺失。
- 命中的知识库必读资料缺失或无法读取。
- 知识库规则与用户要求、项目规则或方案文档冲突且优先级无法判断。
- 方案文档、用户要求与原型之间存在关键冲突。
- 缺少复现条件、期望行为依据或必要权限，无法安全修复。
- 修复范围已经明显超出“最小安全修复”。
