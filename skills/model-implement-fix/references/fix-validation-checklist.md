# 修复验证清单

在标记问题已修复前，至少按下面清单验证。不是每个问题都需要全部项，但要明确写出“适用/不适用”。

## 核心验证项

1. `原问题已消失`
   - 按复现路径再次执行，确认原问题不再出现。
2. `根因路径已覆盖`
   - 确认修复命中了根因，而不是只做表面规避。
3. `相邻流程未被破坏`
   - 检查该功能的上一步、下一步、返回路径、关联列表、详情、编辑、弹窗等关键相邻流程。
4. `权限与数据范围未扩大`
   - 如问题涉及权限、角色、组织、用户范围，确认修复后未意外放大或缩小权限口径。
5. `接口契约未破坏`
   - 如问题涉及接口或 DTO，确认请求和响应仍符合前后端预期。
6. `状态流转正确`
   - 如问题涉及业务状态，确认前置状态、触发动作、后置状态和异常状态都正确。
7. `事务与幂等正确`
   - 如问题涉及写操作，确认重复提交、回滚、重复回调、并发场景没有引入新问题。
8. `原型一致性已恢复`
   - 仅在需要参考原型时适用；确认页面布局、间距、层级、颜色、控件组合或交互表现已尽量贴近原型。
9. `性能未明显恶化`
   - 如问题涉及查询、渲染或批量处理，确认修复没有引入明显性能回退。
10. `必要测试或检查已执行`
   - 记录执行过的测试、构建、lint、接口验证、手工验证或局部回归。

## 结果记录建议

在 `fix-result.md` 中建议按下面口径记录：

- 适用：已验证并通过。
- 不适用：当前问题不涉及该项，并说明原因。
- 待补充：当前无法验证，需要补条件或补环境。
- 失败：验证未通过，需要继续修复。

## 最低要求

无论问题类型如何，至少要覆盖：

- 原问题已消失
- 相邻流程未被破坏
- 必要测试或检查已执行

如果问题涉及写操作、权限或状态流转，还必须额外覆盖对应项。
