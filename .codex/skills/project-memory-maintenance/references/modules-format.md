# Modules 分层格式

## 职责边界

`modules` 只记录当前已经由代码、配置、数据库、运行结果或用户确认核验出的事实。它描述“现在是什么”，不记录某次修改的过程。

- `changes` 记录已经发生的变更、原因、影响、验证和回滚；页面模块不得维护按日期排列的变更日志。
- `plans` 记录尚未完成的大需求或复杂问题的目标、范围和实施安排；计划内容不能当作当前事实。
- `lessons` 记录可复用经验；`guardrails` 记录已授权的项目约束。
- 页面文档记录当前页面目的、边界、数据链路、页面权限、当前兼容契约和页面未决项。
- 跨页面稳定规则放在 `modules/shared/`，页面只记录本页适用的部分并引用共享文档。

## 内容分层

### 全局业务总述

适合放在 `modules/shared/`：

- 核心业务对象、统一状态含义、全局流转和跨流程例外；
- 主要模块协作、数据来源、最终权威系统和外部依赖；
- 通用身份、角色、数据范围和安全原则；
- 跨模块风险、长期未决事项和影响范围；
- 被多个页面共同使用的状态、流转、日志、时效和错误处理契约。

现有 `business-processes.md`、`work-order-status.md`、`work-order-trace.md`、`page-coverage.md` 等共享文档继续作为全局事实入口，先合并内容再新增文件，避免重复。

### 页面事实

页面文件至少说明：

1. 页面目的和业务边界，包括明确不负责的内容；
2. 当前页面行为、接口调用和数据链路；
3. 本页可见、可编辑、可执行的权限范围；
4. 本页特有的状态动作、例外和兼容契约；
5. 当前未确认项、影响和需要的确认方。

页面不记录变更日期、实施过程、测试过程或回滚步骤。确需说明历史原因时只引用 `change_id`，不复制变更正文。

### 接口事实

跨页面使用或契约较稳定的接口，放在 `modules/interfaces/`，按接口族或业务域成组保存，不强制每个接口一个文件。至少记录用途、请求/响应、权限、错误语义、幂等/事务和当前未确认项。页面只记录自己调用哪些接口以及用途。

### 数据表事实

业务表放在 `modules/data/`，原则上一张表一个权威 Markdown 文件。表文件记录表作用、数据权威、字段、主键与关系、状态约束、读写入口和未确认项；完整 DDL 只作为来源，不复制进记忆。表结构变更原因、迁移执行和回滚仍写入 `changes`，计划中的新增/修改/删除写入 `plans`。

## 数据表模板

新增数据库表事实时使用 [module-data-template.md](../assets/module-data-template.md)。一张业务表只保留一个权威文件；没有核验到的字段、关系或物理约束写入未确认项，不根据命名猜测。

## 文件头

### 导航索引

`modules/INDEX.md` 和按需创建的 `modules/<domain>/INDEX.md` 只保留：

```yaml
---
memory_id: MOD-DDYPGZX-INDEX
type: index
updated_at: 2026-10-09
---
```

路径、标题、父索引、正文哈希和覆盖关系由索引脚本根据实际位置和正文推导。导航索引不承担代码证据和 Git 新鲜度核验。

### 事实文档

页面、接口和数据表正文使用轻量头，只保留人需要快速判断的身份和状态：

```yaml
---
memory_id: MOD-TJFX-HF-001
type: module
status: verified
coverage: partial
updated_at: 2026-10-10
---
```

模块事实正文统一使用 `type: module`；页面、共享文档、接口和数据表的层级由 `modules/.audit.json` 中的 `record_level` 表达。文件位于 `modules/<domain>/` 下时，目录已经表达业务域；若该域没有单独 `INDEX.md`，由 `modules/INDEX.md` 和目录文件名完成最小导航。不再重复写 `scope`、`record_path`、`record_anchor`、`parent_id` 或 `aliases`。

机器审计字段（`verified_commit`、`impact_paths`、`evidence_sources`、`relations`、`record_hash`、`working_tree_verified` 等）统一保存于 `modules/.audit.json`，按 `modules/.../*.md` 的相对路径关联。索引和新鲜度脚本从该侧车文件读取，不把审计字段塞回正文头。侧车文件是派生维护数据，缺失或不一致时应报告审计不完整，不得把页面事实改写成已确认。

查询默认返回轻量元数据和正文；需要排查证据时使用查询工具的 `--include-audit` 选项读取审计字段。

## 维护规则

- 新增或修订模块时先检查是否已有共享业务文档，避免在页面复制全局规则。
- 变更完成后更新模块的当前事实；变更过程另写 `changes`，不在模块追加“本轮修改”章节。
- 只读检索或重复核验没有新事实时不刷新正文和更新时间。
- 未确认项保留在对应范围，不用计划、变更或推测填补。
